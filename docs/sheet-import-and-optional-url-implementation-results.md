## 実装した動作

- 表取込では、サークル名・参加日・ブロック・番号をtrim後に判定し、欠落行を除外して続行します。番号「0」は採用します。空行・集計行・CSV形式・通信エラーの既存の扱いを維持します。
- 採用件数と通常除外を数量警告から分け、項目別件数・元の物理行番号・sourceRowIdを保持します。表示例は先頭20行までです。
- 新規作成の最終採用品目が0件なら保存せず入力を保持します。更新で0件になった場合は削除・保護件数を表示し、既存の確認後に反映します。
- 通常更新・更新元切替の診断を、解析からpending差分・AppOverlayLayer・実際の確認モーダルへ中継します。対応関係を選び直した場合も保持します。既存警告の確認条件を維持します。
- URL未入力は完成した品目のurl項目を省略します。既知の任意項目はundefinedだけを省略し、URL以外の空文字列・false・0・有効なnull・未知フィールドを維持します。不正な型は既存検証へ渡します。
- 追加・編集・シート更新・起動・JSON／完全版XLSX復元・保留再試行で同じ規則を使います。編集の変更意図を適用してから正規化するため、URLの削除と未変更を区別できます。
- 必須項目欠落行をURL補完から外します。必須4項目がそろう数量不正行は従来どおりURL補完後に新規追加から除きます。

手動品目・完全版復元の入力条件、購入記録・数量確認・保護設定・照合・ID・配置用参照・操作順序・CAS・イベント世代・保存失敗時の保留処理は既存の仕組みを使用します。

この読込回数は`readApplicationSnapshot`ポートの呼出し数です。内部の個々のreadonlyトランザクション数ではありません。store別put数は要求数で、中断したトランザクションの要求も含みます。成功コミット数とは分けて記録しています。

workerで準備とURL互換対応の両方が必要なB04では、既存の読込内部で準備保存が先に行われます。その後、検証したsnapshotのURLを統一して原子的に保存するため2コミットになります。物理検証前や低水準のDB入口へ変換を移すことは避け、最新rootの再読込と次回の追加保存0回を確認しています。

起動の補助測定はfakeIndexedDB・jsdomと実際の保存アダプター／workerサーバーを使用します。workerサーバーは同一プロセスのloopbackであり、実ブラウザーの別スレッド時間と区別します。下位のIDBトランザクションで試行・成功・中断を数え、store別put要求、snapshotポート読込回数、物理保存時間を別々に記録します。読込時間へ内部保存時間を二重加算しません。

500品目の通常更新を構造検証込みで測定した補助結果では、差分確認までの追加時間は0.49～0.65ms、保存を含む完了時間の差は−0.17～+1.79msです。固定キーの任意項目確認・正規化による小さな追加処理は残ります。全件走査・複製を通常の買い物操作へ持ち込まず、未変更参照と保存経路を維持しています。復元の実ブラウザー解析では500品目XLSXの最大増加が+4.42ms（848.46→852.88ms、約0.52%）でした。正常な復元・通常起動へ追加保存が発生しないことも併せて確認しています。

増加が目立った3ケースはさらに旧版→新版で各20回再測定し、両版とも3件すべて通過しました。150品目・直接方式の更新保存の中央値は、最初の81.81→124.44ms（+42.63ms）に対し、再測定では138.69→125.02ms（−13.67ms）となり、増加は再現しませんでした。worker方式の同条件は122.60→123.78ms（+1.18ms）。画面の自動待機を含む観測値のばらつきとして扱い、最初の値も保持しています。

500品目・直接方式の再試行は、最初の中央値168.66→188.04ms（+19.38ms）に対し再測定183.35→192.28ms（+8.93ms）、95%点213.25→200.48msでした。中央値には約9msの増加が残る一方、実際の再計画・保存を分けた同条件の補助測定は94.32→94.10ms（−0.22ms）で、上位95%点の悪化も再現していません。ブラウザーの値にはクリック、描画、Playwrightの画面待機が含まれ、約9msを正規化処理単独の時間と断定できません。変更による全件走査・追加コミットが通常の再試行へ入っていないこと、保存内容・順序・再確認が一致することを検証したうえで、この観測上の残差を記録し、追加の本体変更は行いませんでした。通常の買い物操作の全条件通過と、初回以外に互換保存を反復しないことを性能維持の判断根拠としています。

補助測定は88ケース・各20サンプルです。更新では画面と同じ構造検証を保存前に実施し、旧版で不正な品目を書き込めた時間を正常完了の比較へ含めません。既存のフル測定ログに対し、更新の検証追加・起動の読込回数追加で再測定した部分だけを置き換えて集計します。

旧版で失敗する必須項目欠落・undefined等のケースは比較不能として分けます。失敗までの短い時間を0msや性能維持として扱いません。通常更新・更新元切替の実ブラウザー比較には、両版で正常保存できるURL入力済みの共通入力を使います。

シート応答は固定CSV、JSONは固定値、XLSXは変更前に生成した同じバイト列を使用します。外部回線の揺れ、人による確認待ちを処理時間へ混ぜません。
