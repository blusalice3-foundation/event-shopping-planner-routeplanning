## 実装と反応時間への配慮

- executionPlacement.ts が所属別の表示投影・配置境界・訪問内スロットの順序変更を提供する。内容だけの編集では準備済みの順序を再利用する。
- hover時のグループ境界・案内先は準備済みインデックスとキャッシュを使用する。省略表示中の論理行も既存の行モデルから参照し、余白では二分探索で実際の周辺境界を調べる。毎回全品目を投影しない。
- 行参照の準備はドラッグで必要になった時だけ行い、通常の買い物操作へ新たな全行割当を加えない。投影済み品目のWeakMapに古い全品目配列や履歴を保持しない。
- 本の上下は本、見出しの上下はスペースを対象とする。所属/訪問境界や混在選択による無効なボタンを有効表示にしない。
- 本の並べ替えは保存時にも訪問の既存スロットへ適用し、先頭本を動かしても別訪問へ基本位置を譲らない。
- ShoppingMoveReceipt.completion で受付と保存完了を区別する。選択解除は完了後に限定し、後続の選択・範囲・日付/モード変更を古い状態で戻さない。
- 確認待ちの所属を推測せず、既存の品目編集画面へつなぐ。数量や優先度だけの編集では確定所属の投影情報を引き継ぐ。
- 操作開始時点で既に存在する日付統合の確認は維持する。受付後に新しく生じた/変化した配置確認とは区別し、内容だけの変更で不要な中止をしない。
- 遅延描画でReactが行のclassを更新しても案内線の位置基準が失われないよう、専用属性と低い優先度のCSS規則を使用する。解除時は以前の属性と別の所有者を保全する。ポインターごとのstyle/座標読取は増やさない。
