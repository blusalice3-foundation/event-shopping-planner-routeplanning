## 実装と検証の要点

- `executionPlacement.ts` が所属別の表示投影・配置境界・訪問内スロットの順序変更を提供する。内容だけの編集では準備済みの順序を再利用する。
- hover時のグループ境界と案内先は準備済みインデックス・キャッシュを使用し、毎回全品目を投影しない。
- カードの上下は本、見出しの上下はスペースを対象とする。所属/訪問境界や混在選択による無効なボタンを有効表示にしない。
- 本の並べ替えは保存時にも訪問の既存スロットへ適用し、先頭本を動かしても別訪問へ基本位置を譲らない。
- `ShoppingMoveReceipt.completion` で受付と保存完了を区別する。選択解除は完了後に限定し、後続の選択・範囲・日付/モード変更を古い状態で戻さない。
- 確認待ちの所属を推測せず、既存の品目編集画面へつなぐ。数量や優先度だけの編集では確定所属の投影情報を引き継ぐ。
- 新しいブラウザ試験は通常のPWA起動と実UIのバックアップ復元を使用する。D&Dのイベント試験と、実際のクリック/タップの確認を区別する。
