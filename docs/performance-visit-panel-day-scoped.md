# 訪問先パネルの残存経路を日付に限定

2026-10-10。並び替え、取り消し、確定と、それらを伴う長押しモード変更を日付差分コマンドへ移した。この変更の処理時間は再測定していない。[既存の性能記録](performance-day-scoped-completion.md)の数値は追加変更前のビルドの結果。

## 対象と処理

[訪問先コマンド](../src/app/commands/useMapVisitListCommands.ts)は `dayMutation: { kind: "visits", eventName, day, mapKey, order?, modeDay? }` を指定する。並び替えと取り消しは希望するID順序を送り、確定はWorkerが持つ最新の保存済み順序を使う。長押しの確定・破棄は同じコマンドに切替先の日付を含める。パネルを開く前の日付統合も `kind: "day-merge"` で対象日付に限定する。

[共通の計画処理](../src/features/consistency/domain/visitPanelMutation.ts)をWorkerの通常処理とUIの確認処理で共有する。外部から追加された訪問先、ホール別の順序、保存ルート、所属と優先度の規則、履歴の取り消し基準を維持する。UIの計画処理を経由しない通常処理でも履歴を更新し、キュー待機中に終了したパネルの操作はWorker送信前に拒否する。

長押しが別日付を指す場合、[処理範囲](../src/features/consistency/domain/dayScope.ts)を訪問元と切替先の2日付に広げる。読取・整合性検査・差分応答・キャッシュ照合・書込み範囲の検査に同じ範囲を渡す。全イベントの読取や複製には進まない。品目は既存のイベント単位レコードを読むが、他イベントの品目や対象外の日付のマップ・子レコードは読まない。

[永続化](../src/persistence/db/atomicRestoreTransaction.ts)は全storeのrevision・checkpointによる競合確認を維持し、訪問元の実行ID・ホール別訪問先・保存ルート・整合性情報と切替先のモードを1トランザクションで保存する。第三の日付への変更を拒否し、1日付のキャッシュを2日付の要求に流用しない。保存失敗では両日付を巻き戻し、他タブとの競合では範囲を限定した再読取で再試行する。

日付統合は `readDay` / `commitDay` で確認・再確認する。訪問元の統合確認に、切替先のモードの変更前後も含め、確認中の他タブ変更を見落とさない。UIへの採用では対象外の日付と過去イベントの参照を保持する。DBバージョンは11。表示位置も日付レコードに移し、DB 10以前の既存保存を起動時に検証・移行する。旧10クライアントの接続・書き戻しを拒否する。マップを閉じる際の表示位置は、訪問元の日付を明示する独立した `map-viewport` コマンドで保存し、長押し後の全体保存も除く。

## 検証

単体・統合・Workerの221ファイル、2,413テストが成功した。今回追加した22テストには以下を含む。

- キャッシュなし、過去0件／10,000件での並び替え・取り消し・確定・別日付への長押し確定／破棄。cursor走査なし、小さな7ヘッダーだけの `get("data")`、過去イベントと第三の日付のキーを読まないことを検査。
- 実行ID・ホール別訪問先・保存ルートの一致、2日付の保存失敗と再試行、実際のCAS競合での他タブ更新の保持。
- 1日付と2日付のキャッシュの区別、第三の日付の改変拒否、差分応答と過去データの参照保持。
- 日付統合の確認中に切替先のモードを他タブが変更した場合の再確認。全体読取・全体保存を呼ばないこと。
- WorkerがUIの計画関数を省略した場合の履歴基準の更新、終了したパネル操作の送信前拒否。
- 表示位置の保存を過去0件／10,000件で範囲限定し、別日付・別イベントを保持。署名付きDB 10の表示位置をDB 11へ移行し、10クライアントを拒否。

[Workerの検証](../src/persistence/worker/visitPanelCommands.worker.test.ts)、[UIコマンドの検証](../src/app/commands/useMapVisitListCommands.test.tsx)、[キューの検証](../src/app/commands/applicationMutationCoordinator.test.ts)を参照。

本番形式のビルドを使うChromiumのブラウザー回帰31ケースも成功した。公開の復元UIでアクティブ500件・過去10,000件を実復元し、IndexedDBの件数を検査した上で、罫線・色付き40,000セルと2ホールで並び替え・取り消し・確定・長押し確定／破棄を操作した。送信が `day` コマンドで、全体の `read` / `commit` / `restore` に進まないことと、再読込後の訪問順を検査した。

別日付への長押し確定／破棄では、訪問元と切替先の変更を1つの `visits` コマンドで保存し、マップ終了時の表示位置の保存も `map-viewport` コマンドになることを実画面で確認した。日付統合の取消・保存失敗・再試行、確認中の他タブ変更による再確認、同一内容のイベント置換後に古い履歴操作が拒否されるケースも含む。

DB 11を受け入れるXLSX公開操作・性能記録の関連33テスト、本番形式ビルド、型検査、ESLint、書式、アーキテクチャ境界、テスト分類、DB互換性、文字コード、差分空白検査も成功した。今回のブラウザー検証は機能と送信範囲の検査であり、時間計測の結果として扱わない。既存ファイルのUTF-8・BOMなし・改行コードを維持した。
