# 描画・レスポンス高速化の実装と検証

通常の品目編集を差分コマンドに切り替え、経路計算と保存の重い処理を専用Workerへ移した。画面外には高さと移動先を持つ軽い行を残し、カードの操作部品を解放する。

- [品目編集](../src/app/state/useApplicationSnapshot.ts): `updateItemFields({ eventName, itemId, changes, baseline })`で変更項目を受け付ける。数量・限数購入の正規化と保護レベルの自動昇格を受付時と保存時に適用し、対象イベントの配列と対象品目だけをコピーする。未保存入力を保持し、他タブとの項目単位の競合は既存の確認画面で扱う。構造変更には従来の経路を残す。
- [経路計算](../src/features/map/routing/useRouteCalculation.ts): 通行条件、訪問順、座標、優先度、ホール境界・判定規則をキーにする。価格・数量・メモだけでは再探索しない。探索・簡略化・境界検査はWorker内で行い、変更された要求を中断して最新条件に一致する結果だけを採用する。地図からの経路挿入は最新結果を待つ。
- [経路キャッシュ](../src/utils/pathfinding.ts): ホールの頂点と`inside-inclusive-v1`規則を保存可能なデータとしてキーに含める。並べ替えでは一致する先頭区間だけを再利用し、その経路による重複ペナルティを復元して以降を順に再探索する。
- [表示範囲管理](../src/features/shopping-list/renderers/ViewportContent.tsx): 表示範囲と前後500pxの操作部品を保持し、範囲外では高さを測定済みの軽量行へ戻す。フォーカス、直接編集した未保存入力、編集ダイアログ、ドラッグの対象を保持する。一括操作では全対象のカードを保持せず、現在入力中の品目だけを保持する。タイトルの展開状態は品目ID別の外部状態に残し、一覧と集中モードでカードの解放後も復元する。検索移動では対象を生成してからスクロールし、印刷時だけ全件を表示する。
- [ズーム](../src/features/shopping-list/renderers/RetainedViewportListRenderer.tsx): アプリの表示倍率とブラウザの表示倍率を反映し、表示中の先頭品目と画面上の位置を基準にスクロールを補正する。拡大・ダイアログ・ドラッグで全件描画へ切り替えない。
- [地図操作](../src/features/map/canvas/useCanvasViewport.ts): ピンチ・ホイールの最新値を即時に保持し、画面更新を1フレームに1回へ集約する。経路交差は地図座標でキャッシュする。操作中は直前の画像を変換して描き、終了後に再描画する。
- [検索](../src/components/SearchBar.tsx): 入力値を検索欄で保持し、結果更新を遅延可能にする。検索文字列は品目の参照ごとにキャッシュする。日本語変換中のEnterでは移動せず、「次を検索」は最新の入力値を使う。
- [保存](../src/persistence/adapters/workerPersistenceCommandAdapter.ts): 通常操作では項目差分と操作番号を送る。隣接する編集は確認・構造変更をまたがず順序を保って一括確定する。全領域の実データ検査、ハッシュ照合、競合検査、IndexedDBトランザクションの開始から確定までをWorker内で完結する。応答も差分にし、保存失敗時は入力を保留して再試行する。購入操作に新たな待機時間は加えず、メモの既存の300ms待機・最大1,000msを維持する。初期移行・復旧候補の採用は既存のブラウザ側の処理を残す。

実測は2026-10-08、Windows上のPlaywright Chromium、1280×720、各条件1回。すべての条件に4万セルの地図と過去イベント合計1万品目を含めた。元の実測値は[JSON記録](performance-response-samples.json)に保存した。変更前との同条件比較や端末横断の性能保証は行っていない。

[ブラウザ検証](../tests/browser/responsive-performance.spec.ts)ではカード数45未満、option数が表示カード数に比例する上限へ戻ることを検査する。拡大時の先頭行位置、拡大中の編集・競合ダイアログ、対象カードの保持、日本語変換中のEnter、購入直後の移動、Worker保存失敗時の入力保持・再試行・再読込、他タブとの競合を確認した。

検証結果: 単体1,702件、統合532件、Worker74件、ブラウザ126件を確認。型検査、変更ファイルのESLint、整形、アーキテクチャ境界、テスト分類、文字コード、`git diff --check`も確認した。`npm run build:app`でアプリとWorkerを生成した。

通常のブラウザ検証を再実行する場合は`npm run build:app`の後に`node node_modules/@playwright/test/cli.js test --workers=1`を使う。測定だけなら末尾に`tests/browser/responsive-performance.spec.ts`を指定する。PlaywrightのJSONレポーターを有効にすると`response-timings`添付から数値を取り出せる。

`verify-release-a-build.mjs`の本番リリース検証は、未コミットの変更がある状態を受け付けない。今回のソース変更は未コミットのため、このリリースゲートは通していない。アプリのビルドとローカルの動作検証は成功している。

既存ファイルのUTF-8・BOM有無・改行コードを維持した。追加ファイルはUTF-8（BOMなし）・LF。保存後に再読込し、日本語の代表文字列と文字化け・不自然な`?`・BOM・改行の検査を実施した。
