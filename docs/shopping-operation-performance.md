# 実行・集中モードの品目操作と差分描画

購入変更・回答記録・限数の実購入数・一括操作は、最新の受け付け済み状態へ差分を反映する共通コマンドを使う。操作の受け付けと保存完了を分離し、次への移動では保存完了を待たない。

## 実装

- `useShoppingItemMutationCommands.updateItems` と `useApplicationSnapshot.updateItemFields` は、複数品目も一つの操作として受け付ける。操作番号と対象IDを保存キューで保持し、既存の数量正規化・保護レベル・競合判定を通す。
- `itemIndex` は品目IDの索引と変更位置を共有する。品目配列の内容変更ではIDの配列を保持し、最新値を読む不変の索引ビューを定数時間で作る。回答記録と移動時の検査は、この索引から最新状態を読む。変更履歴の親配列は弱参照で持ち、保存済みの配列を履歴として蓄積しない。
- `executionVisitIndex` は品目と訪問先の所属、訪問先順序を保持する。内容変更では対象訪問先の品目配列を更新し、購入済み件数・残額を差分で更新する。追加・削除・復元・所属や順序の変更では再構築する。
- 実行モードの状態フィルター、一時表示、候補、検索、行情報は変更品目だけを再評価する。変更されていない配列、行オブジェクト、所属ID、アクセシビリティの情報を保持する。ブロック・重複・移動計画の情報は、それぞれの関連フィールドが変わったときに再計算する。
- 後回し・遅参のフェーズ開始時に固定するIDと一時表示の規則を維持する。変更されていない訪問先を再利用し、対象訪問先のフェーズ所属を再評価する。ナビゲーションの索引は対象訪問先のバケットだけを更新し、一括変更でも各フェーズの配列・索引は一度だけ複製する。
- 実行モードのスペースとプレースホルダー、集中モードの品目をメモ化する。操作関数・ホール定義・未変更品目の参照を維持し、保存通知だけでカードの描画をやり直さない。描画関数はReactの確定済みpropsとして渡し、中断された並行描画の内容が保持行に混ざらないようにする。
- メモ化したスペースの内部にも保持対象の変更を伝える。アプリの編集・削除対象は集中モードにも渡す。確認画面を開いたままスクロールしても対象カードを保持し、閉じた後は解放する。
- 画面外のカード操作部品を解放する。入力値は受け付け済み状態、展開状態は外部の行状態に保持する。フォーカス・編集・確認画面の対象を保持し、保存待ちだけでは保持しない。対応ブラウザでは、測定済みの高さ、またはプレースホルダーの固定高さを持つ画面外の行のレイアウトを `content-visibility` で省略する。
- 実行モードの表示位置は、継続するDOM監視と表示範囲の候補から解決する。訪問先のID索引と対象行への直接検索を使い、次の訪問先一つを先読みする。移動と先読みが重なる間は保持要求を数える。
- 集中モードは次の正式な訪問先の最大2品目を準備し、到着時に操作部品を再利用する。直前の訪問先が80品目以上の場合はその行DOMを1か所だけ保持し、戻る際の再構築を減らす。非表示中の操作部品は解放し、さらに先へ進んだらその訪問先も破棄する。一時表示・確認移動ではこの保持を解除する。
- 集中モードの地図は、経路用の入力と購入状態の入力を分離する。座標索引、ホール・経路設定、経路キー、背景・経路の描画を再利用する。Workerの応答は要求番号と経路条件を照合し、古い応答を棄却する。購入変更では対象セルの集計・ラベル、移動では以前と新しい位置マーカーだけを更新し、未変更の座標・状態・ラベルを保持する。
- カード操作には直前の受け付け済み状態を弱参照のメタデータで関連付ける。同一フレームで状態を一巡して描画時と同じ状態に戻っても、最後の操作を取りこぼさない。このメタデータは保存内容へ混ぜない。
- 「記録」の回答と実購入数は、通常メモの入力待機と分けて即保存キューへ入れる。内容が同じ記録でも待機中のメモを流す。保存通知の内容が同じ場合は品目参照を維持し、他タブの変更は該当品目へ反映する。

既存の差分通信、Workerによる全領域の整合性検査、保留、再試行を維持する。配列のコピーやReactの行照合まで完全な定数時間になる設計ではなく、全品目の再集計・全カードの描画・経路形状の再構築を品目操作から外す設計である。

## 計測

計測は初期状態で無効。開発者コンソールで有効にしてから操作する。

```js
window.__espShoppingPerformance.enable();
window.__espShoppingPerformance.reset();
// 購入、記録、移動などを操作する。
window.__espShoppingPerformance.read();
window.__espShoppingPerformance.enable(false);
```

`input` は共通コマンド・移動処理の受け付け時間、`paint` は次の描画機会までの時間、`save` は保存キュー投入からコミットまでの時間。直近500サンプルとコンポーネントの描画回数を保持する。品目の内容は記録しない。`paint` とブラウザ検証の反応時間は `requestAnimationFrame` と後続タスクを使った推定値であり、実機の入力遅延や画素表示完了そのものではない。

```powershell
npm run build:app
npx playwright test tests/browser/responsive-performance.spec.ts --workers=1 '--reporter=list,json'
```

JSONレポートの `shopping-operation-timings` 添付には、操作別の生サンプル、中央値、95%点、保存時間、描画回数を含む。必要なら `PLAYWRIGHT_JSON_OUTPUT_NAME` に出力先を指定する。`ESP_PROFILE_SHOPPING=1` を設定すると、実行モードのCPUプロファイルも添付する。`ESP_ENFORCE_SHOPPING_BUDGET=1` を設定すると、1,500品目の実行購入・実行記録・集中購入・集中記録・次へ・戻るを、それぞれ20サンプル以上、中央値50ms以下、95%点100ms以下で検査する。

## 検証範囲

150・500・1,500品目、訪問先の分散と同一スペースへの集中、40,000地図セル、10,000履歴品目を使う。実行モードの全件閲覧後の連続購入、集中モードの購入・売切回答記録・記録直後の次への移動、地図の購入表示、数量・メモ入力、ズーム時の保持、編集対象の保持、スマートフォン幅をブラウザで確認する。

単体・結合テストでは、数量正規化、一括操作、限数の記録、戻る、フェーズの固定対象と切替、一時表示、連続操作の順序、未変更カードの描画停止、保存通知の参照維持、Workerの古い応答を確認する。保存Workerの書き込み失敗・再試行・再読み込みと、他タブの変更・競合の解決もブラウザで確認する。

スマートフォン実機は未検証。中央値50ms以下・95%点100ms以下は、この環境のブラウザ反応時間を使う暫定目標であり、保存完了時間には適用しない。
