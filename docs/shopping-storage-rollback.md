# 旧バージョンへ戻すための保存形式の準備

現行版の高速な列間移動は、eventListsを認証付きの分割形式で保存する。計画基準版 `200cd7564772a17e2264907ae22e9a93ad30f5dc` はこの形式を直接読み込めない。DB versionは11のままなので、製品コードだけを旧版へ切り替える前に、現行版で次の準備を行う。現行版でのデータ破壊を意味するものではない。

## 操作手順

1. 通常画面で保存が終わったことを確認し、本アプリのほかのタブ・ウィンドウを閉じる。保存失敗や復旧待ちがある場合は、通常の復旧を先に完了する。
2. 現行版と同じ配信元・同じブラウザprofileで `/?maintenance=storage-rollback` を開く。PWAを使っている場合も、同じ配信元のURLを開く。この専用画面は通常のアプリと保存Workerを起動しない。
3. 「1. 最新のバックアップを保存」を押し、ダウンロードしたJSONを保管する。保存確認のチェックを入れる。
4. 「2. 旧バージョン用に準備」を押し、完了表示を待つ。バックアップを取得してから保存状態が変わっていれば準備は拒否されるので、最新のバックアップからやり直す。
5. 専用画面を閉じてから旧版へ切り替える。配信元とprofileを変えずに起動し、品目・数量・メモ・実行順・地図を確認する。確認が済むまでバックアップを保管する。

準備は最新の論理データを旧版が読めるeventListsの全体形式へ戻す処理であり、過去のデータへの巻き戻しではない。品目・別日・他イベント・任意項目・地図を削除しない。全storeの基準照合、eventListsの本体・認証metadata・checkpoint・sidecarのrevision・保存モードの変更を同じtransactionで行う。競合や書込失敗時は一組として取り消す。

準備後に現行版を再び開いても、分割形式へ自動変換しない。保存は従来の汎用経路を使う。これは旧版への復帰を保つための明示的な保守モードであり、通常の高速経路の性能合格をこのモードへ適用するものではない。旧版への切替を中止する場合も、データを削除して初期化しない。

## 再現可能な検証

```powershell
node scripts/verify-shopping-storage-rollback-baseline.mjs --baseline-root D:/esp-dnd-plan-20261021
```

この検証器は、指定先が正確な基準コミットでソース変更がないことを確認し、使い捨てのfake-indexeddbで現行版と基準版の実loaderを動かす。準備前の旧版読込拒否、準備後の全store一致、旧版の書込から現行版への再読込、旧版の日scope読込と保守markerの保持を確認する。利用者のブラウザprofileやDBには接続しない。実ブラウザの専用画面・ダウンロード・再起動は `tests/browser/shopping-storage-rollback.spec.ts` で別に検証する。
