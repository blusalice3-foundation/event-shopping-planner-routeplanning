# 共通の描画処理の高速化

カードごとの金額・数量の選択肢と数値ラベルを共有する。小規模一覧・仮想リスト・集中表示では共通のReact要素を再利用し、80件以上のカードを全件描画する一覧では、非表示のDocumentFragmentの雛形を複製して選択肢をまとめて設定する。カードの生成時に方式を決め、同じカードの生存中は固定するため、件数や描画条件が変わっても入力フォーカスとDOMの管理方法が変わらない。

金額102種類と数量1〜20、価格未定・0円、標準外の現在値と並び順を維持する。全選択肢を最初の表示前に用意し、ネイティブの選択UI・value・disabled・aria-label・変更ハンドラーを維持する。雛形から実際のDOMを共有せず、コントロールの種類が変わる場合は正しい雛形で作り直す。ラベルはtextContentで設定する。

文字の省略判定はResizeObserverを共有し、全カードの幅を読み取ってから、変化した判定結果だけを一括更新する。元の1pxの判定幅、展開・折り畳み、リサイズ追従を維持し、更新は次の表示・入力より前に完了する。解除済みのカードへは通知せず、最後のカードの解除時に監視を終了する。

アプリの状態更新、変更計画、確認、保存キュー、整合性・競合・破損の検証、保存確定処理は従来の共通経路を使用する。前の保存高速化も維持する。

## 参加日の切り替え

Windows 11、Node 24.19.0、Playwright 1.62.1付属のheadless Chromium。PCは1280×900、スマートフォン配置はPC上でアプリの表示設定を切り替えた390×844。実機のスマートフォンでの測定ではない。新しい独立したブラウザー保存領域に通常のバックアップ復元UIで1イベント・2日分を取り込み、通常のHTTP配信の本番バンドルで測定した。修正前は0592ca9、修正後は今回の変更を含むソース。計測中はテスト・ビルドを同時実行していない。

[実測サンプル](rendering-performance.samples.json)には比較前後の全サンプル、測定したソースと本番バンドルのSHA-256を記録した。マップ表示だけのケースはカード描画を使用せず、約26〜27msで推移した。大量の全件表示ではDOM作成・スタイル計算の負荷が残る。測定値はこの合成データ・端末でのローカル診断であり、全操作・全端末で同じ短縮率を保証する値や、正式なリリース性能承認の証跡としては使用しない。

## 回帰検証

比較キーの網羅、複数カードの独立した選択値、規格外の現在値、価格未定・0円、読み取り専用、文字幅の閾値・変更・リサイズ・展開、解除・再登録・監視終了を検証する。描画方式の選択条件が変わってもフォーカス・DOM・選択肢数が維持されることを確認する。

実ブラウザーではPCとスマートフォン配置の100件表示で、標準外の価格・数量、価格未定から0円への変更、数量変更、別カードとの分離、保存確定、参加日を往復した後の値を確認する。既存の購入状態・確認・保存失敗・再試行・復旧のテスト、品質・ブラウザー・ロールバックの検証も継続する。
